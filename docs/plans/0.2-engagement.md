# Feature 2: Profile Foundation and ICP Engagement
**Release:** `v0.2-engagement`

## Intention
Help the sender prepare a credible profile for the selected ICP and recommend useful, relevant engagement without requiring live LinkedIn automation.

## User Outcome
A user can audit profile positioning, import or provide recent posts, review relevance and cooldown decisions, approve grounded like/comment recommendations, and execute them through FakeExecutor or ManualExecutor.

## Scope
- Advisory profile audit covering headline, About, proof, featured items, services, and CTA.
- ICP-aligned post source boundary using fixture or manual inputs.
- Recency, content quality, author eligibility, blocklists, duplicate detection, and same-author cooldown.
- Evidence-grounded comment generation and quality checks.
- Mandatory human approval, edit, reject, skip-author, and pause controls.
- Persistent recommendations, decisions, results, provenance, and audit events.

## Domain States
Engagement eligibility is separate from qualification and campaign enrollment: `NOT_EVALUATED`, `REVIEW_REQUIRED`, `APPROVED`, `PAUSED`, `NOT_ELIGIBLE`. Recommendations and executed actions have their own action and approval states.

## Contracts
Post sources and AI generation use provider interfaces. Engagement services call `LinkedInExecutor` only through domain contracts and must work with FakeExecutor and ManualExecutor. Generated comments must cite the post evidence used and must reject invented claims, generic praise, sales pitches, and repetition.

## Persistence and Migrations
Add tenant-scoped profile-audit reports, post records, engagement recommendations, approvals, cooldown records, and action results through reviewed Drizzle migrations. Preserve original and edited content.

## Implementation Boundaries
No live feed scanning, browser execution, automatic profile editing, or unapproved publishing belongs in this release. Playwright begins only in Feature 5.

## Tests
Test profile scoring, post filters, recency, blocklists, duplicate and cooldown behavior, grounded comment validation, mandatory approval, tenant isolation, and Fake/Manual executor audit results.

## Offline Demonstration
Audit a sender profile, load fixture posts, generate recommendations, approve/edit one comment, reject another, execute through ManualExecutor, and inspect the persisted result.

## Human Approval
The project lead approves profile criteria, engagement eligibility rules, comment quality policy, approval UX, and the offline demonstration.

## Release Gate
Feature 2 is complete only when advisory profile audit and approved offline engagement work end to end with persistent provenance and audit history. The release tag is `v0.2-engagement`.
