# Feature 1: Target Audience and ICP Pipeline
**Release:** `v0.1-icp`

## Intention
Turn imported prospect data into qualified, evidence-backed, human-approved audiences without live LinkedIn scraping or outreach.

## User Outcome
A user can define an ICP, import a CSV or fixture source, review validation and duplicate results, qualify prospects deterministically and with AI, approve or reject review cases, and export prospects that are ready for a campaign.

## Scope
- Generic ICP criteria: titles, seniority, industry, company size, geography, keywords, positive and negative signals, hard exclusions, scoring thresholds, and evidence requirements.
- `ProspectSourceAdapter` boundary with CSV and fixture implementations.
- Original and canonical LinkedIn URLs, normalized fields, raw provenance, and database-backed tenant deduplication.
- Deterministic filtering before AI evaluation. Hard exclusions cannot be overridden by AI.
- Provider-independent structured AI evaluation with a fake provider for offline tests and Gemini as an optional implementation.
- Score, confidence, decision, factors, evidence, reasoning, missing information, model metadata, and validation result.
- Configurable routing to qualified, review, or rejected.
- Separate campaign readiness and human review with audit events.
- Resumable import batches and export of `READY_FOR_CAMPAIGN` prospects.

## Domain States
- Qualification: `PENDING`, `QUALIFIED`, `REQUIRES_REVIEW`, `REJECTED`.
- Campaign readiness: `NOT_READY`, `READY_FOR_CAMPAIGN`.
- Import batch: `CREATED`, `VALIDATING`, `PROCESSING`, `PARTIALLY_COMPLETED`, `COMPLETED`, `FAILED`, `CANCELLED`.

Qualification does not enroll a prospect in a campaign.

## Contracts
- `ProspectSourceAdapter.validate()` and `.ingest()` accept source-specific input and emit raw prospects with provenance.
- `AIProvider.generateStructured()` receives task, prompts, schema, evidence, and timeout settings and returns validated metadata.
- URL canonicalization must reject invalid URLs rather than mapping them all to one sentinel value.
- Every repository operation requires tenant context and preserves tenant ownership.

## Persistence and Migrations
Persist ICP definitions, import batches, prospects, evaluations, evidence references, review decisions, and audit events through reviewed Drizzle migrations. Enforce `UNIQUE (tenant_id, normalized_linkedin_url)`. Use database upsert semantics rather than read-then-insert logic.

## Implementation Boundaries
No live LinkedIn discovery, profile scraping, campaign enrollment, message sending, likes, comments, or browser execution belongs in this release. Gemini calls are optional and never required for automated tests.

## Tests
- ICP schema and routing thresholds.
- URL canonicalization and invalid-input handling.
- CSV validation, provenance, and same-file duplicates.
- Cross-import and concurrent database deduplication.
- Deterministic hard exclusions before AI.
- Fake AI structured output, malformed output, timeout, and provider failure behavior.
- Persistent evaluation history for deterministic, AI, and manual decisions.
- Resuming a partially completed import without duplicate processing.
- A 100-prospect offline pipeline demonstration with no external calls.

## Offline Demonstration
Create an ICP, import synthetic CSV data, show invalid rows and duplicates, run deterministic and fake-AI qualification, approve review cases, export ready prospects, restart/resume the batch, and inspect evidence and audit events.

## Human Approval
The project lead approves the criteria schema, routing thresholds, evidence policy, AI provider metadata, review workflow, export format, and offline demonstration.

## Release Gate
Feature 1 is complete only when the persistent pipeline, database deduplication, evaluation history, review/readiness separation, resumability, exports, isolation, and offline tests pass. The release tag is `v0.1-icp`.
