# Feature 5: Safety and Supervised Execution
**Release:** `v0.5-supervised-execution`

## Intention
Connect already-tested business workflows to a visible browser in a controlled, individually approved manner. Live LinkedIn execution remains operationally risky.

## User Outcome
An operator can verify a persistent session, start a supervised run for one controlled account, approve individual actions, observe the visible browser, stop execution, and recover safely from checkpoints or uncertain outcomes.

## Scope
- PlaywrightExecutor behind the existing executor interface.
- One browser owner and account lease per LinkedIn account.
- Encrypted session storage with key/version boundary and redacted logs.
- Working hours, account-specific budgets, cooldowns, approvals, tenant/account/campaign/global kill switches.
- Account health states, checkpoint/CAPTCHA detection, automatic account pause, and reauthentication workflow.
- Selector fixtures, fallback strategy, page-state verification, evidence capture, and selector versioning.
- Incremental enablement: session verification, visit, like, approved comment, connection, approved DM, follow-up, then synchronization.

## Domain States
Account health is separate from action and enrollment state: `HEALTHY`, `WARNING`, `PAUSED`, `CHECKPOINT_DETECTED`, `REAUTH_REQUIRED`, `DISABLED`. An uncertain external result is never treated as a successful send.

## Contracts
The executor must verify external state after each action and return success, failure, or uncertainty. Business logic enforces lease, budget, approval, health, working-hours, and stop-on-reply checks before dispatch.

## Persistence and Migrations
Add session metadata, selector versions, execution evidence, account health transitions, and safety events through reviewed Drizzle migrations. Never persist raw secrets in audit payloads or logs.

## Implementation Boundaries
This is supervised execution, not undetectable or unattended automation. A personally controlled test account and explicit project-lead approval are required before enabling each capability. No scaling is part of this release.

## Tests
Test selectors against fixtures, session ownership, lease and budget bypass prevention, kill switches, checkpoint detection, secret redaction, external-result verification, uncertain-action reconciliation, and visible-browser manual acceptance.

## Offline Demonstration
Run the executor against Playwright fixture pages first, then one visible supervised action on one approved test account. Demonstrate budget denial, checkpoint pause, kill switch, and uncertain-result handling.

## Human Approval
The project lead approves session handling, selectors, account, delay and budget configuration, each enabled action, test-account pilot, and movement beyond supervised operation.

## Release Gate
Feature 5 is complete only when one controlled account passes the approved supervised pilot and all safety, recovery, redaction, and kill-switch tests pass. The release tag is `v0.5-supervised-execution`.
