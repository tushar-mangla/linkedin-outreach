# Feature 6: Tracking, KPIs and Optimization
**Release:** `v1.0-linkedin`

## Intention
Explain which ICP, engagement, message, and sequence combinations produce replies, opportunities, and meetings while preserving auditable raw history.

## User Outcome
A user can inspect tenant-safe funnel metrics, trends, safety events, campaign and ICP comparisons, experiment results, and CSV/API exports that reconcile to raw events.

## Scope
- Raw domain and audit events for ICP, engagement, outreach, commercial outcomes, and safety.
- Funnel: imported, qualified, ready, enrolled, connections sent, accepted, DMs sent, replies, positive replies, opportunities, and meetings.
- Daily reproducible rollups by tenant, account, campaign, ICP, segment, score band, geography, industry, message/prompt/sequence version, step, engagement status, date, and execution mode.
- Test-data exclusion, tenant isolation, stable deterministic A/B assignment, and exports.
- Acceptance/reply synchronization through an executor/provider boundary.
- Analytics dashboard with definitions and reconciliation indicators.

## Domain States
Analytics derives metrics from immutable events. Cached rollups are performance artifacts and never replace raw events or lifecycle state.

## Contracts
Synchronization produces idempotent events. Analytics definitions document numerator, denominator, attribution window, test-data policy, and timezone. Experiment assignment is fixed for an enrollment.

## Persistence and Migrations
Add domain event, synchronization, rollup, experiment assignment, and commercial outcome records through reviewed Drizzle migrations. Rollups must be reproducible from raw events.

## Implementation Boundaries
Analytics does not silently mutate campaign state. Live synchronization is available only after Feature 5 approval; fake and manual sources support offline tests and demonstrations.

## Tests
Test funnel calculations, rollup rebuilds, event idempotency, attribution, stable A/B assignment, test-data exclusion, tenant isolation, synchronization with fake data, and dashboard API/export responses.

## Offline Demonstration
Use FakeExecutor and fixture events to show zero-state metrics, accepted connections, replies, positive replies, opportunity attribution, rollup rebuild, dashboard updates, and export reconciliation.

## Human Approval
The project lead approves funnel definitions, attribution rules, experiment policy, dashboard metrics, test-data handling, and the offline demonstration.

## Release Gate
Feature 6 is complete only when dashboard and exports reconcile with raw events, remain tenant-safe, and support documented comparisons and experiments. The release tag is `v1.0-linkedin`.
