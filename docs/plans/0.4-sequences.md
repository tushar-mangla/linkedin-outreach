# Feature 4: Multi-Touch Sequencing
**Release:** `v0.4-sequences`

## Intention
Turn approved prospects, engagement, and message packages into reliable conditional workflows that operate fully through FakeExecutor or ManualExecutor.

## User Outcome
A user can create an immutable sequence version, enroll approved prospects, schedule actions and waits, pause or cancel enrollment, stop immediately on reply or opt-out, and inspect every transition.

## Scope
- Campaigns, immutable sequence versions, ordered steps, delays, conditions, approval requirements, message versions, attempt limits, and failure policies.
- Enrollment state separate from action state.
- Visit, like/comment recommendation, connection, message, acceptance check, and reply synchronization steps.
- PostgreSQL-backed scheduled action queue with idempotency keys and `SKIP LOCKED` claiming.
- Account lease and daily budget checks before execution.
- Pause, resume, cancel, completion, failure, and uncertain-action recovery.
- Transactional stop-on-reply: persist reply, stop enrollment, cancel pending outbound actions, and audit together.

## Domain States
Enrollment states include `ENROLLED`, `ACTIVE`, `WAITING_CONDITION`, `ACTION_PENDING`, `STOPPED_REPLY`, `OPTED_OUT`, `PAUSED`, `CANCELLED`, `COMPLETED`, and `FAILED`. Actions use the shared action state vocabulary and must not be collapsed into enrollment state.

## Contracts
Every action uses `LinkedInExecutor`. Before each outbound action, synchronize the thread, verify enrollment and approval, acquire the account lease, reserve budget, and check account health. Uncertain sends are reconciled, not automatically retried.

## Persistence and Migrations
Add campaigns, sequence definitions and versions, steps, enrollments, scheduled actions, reply events, and transition/audit events through reviewed Drizzle migrations. Sequence versions used by an enrollment are immutable.

## Implementation Boundaries
No live LinkedIn browser is required. Playwright is explicitly deferred to Feature 5. Scheduling must be testable with an injected clock and executor.

## Tests
Test version immutability, delay and condition evaluation, acceptance-dependent steps, idempotent claiming, lease and budget enforcement, pause/resume/cancel, crash recovery, uncertain actions, and stop-on-reply versus pending send using PostgreSQL and offline executors.

## Offline Demonstration
Run a multi-step sequence with FakeExecutor and ManualExecutor, simulate time, acceptance, a reply, and an opt-out, then show pending actions cancelled and the complete transition audit.

## Human Approval
The project lead approves sequence states, stop conditions, retry policy, action claiming, budget/lease order, and the offline demonstration.

## Release Gate
Feature 4 is complete only when approved fake/manual campaigns execute conditionally, recover safely, and stop transactionally on reply or opt-out. The release tag is `v0.4-sequences`.
