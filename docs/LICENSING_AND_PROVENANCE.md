# Licensing and Provenance

## Policy

External repositories are references unless code reuse is explicitly approved. Before adapting code, record the repository, commit, license, files, change description, notices required, and intended distribution boundary.

## Reference Repositories

- **OpenOutreach:** behavioral reference for ICP and prospect qualification. Do not copy GPL code into the proprietary core without accepting the applicable obligations.
- **Linki:** product and workflow benchmark. Treat its custom Sustainable Use License as restricted until permission is confirmed.
- **linkedin-engage:** behavioral and safety reference. MIT code may be adapted only with required notices and a provenance record.
- **linkedin-outreach-automation:** conceptual reference until its license is verified.
- **linkedin-outreach-agent:** architecture reference; do not assume its maturity or copy its implementation without review.

## Current Repository Status

The RecruitmentOS implementation is custom. No external source files are currently approved for incorporation. Common libraries listed in `package.json` are ordinary dependencies and are managed through their own licenses.

## Approval Gate

The project lead must approve any externally adapted code before merge, including license compatibility, required notices, security review, multi-tenant changes, and provenance updates.
